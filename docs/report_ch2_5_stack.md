# 2.5 Выбор программного стека и инструментов разработки

Для реализации веб-приложения «Платформа для поиска команд в онлайн-игры» был выбран стек технологий, позволяющий разделить клиентскую и серверную части, организовать работу с базой данных и обеспечить дальнейшую контейнеризацию проекта. При выборе инструментов учитывались требования курсовой работы, необходимость реализации CRUD-функционала, аутентификации, авторизации, ролевой модели и последующего развертывания приложения.

Клиентская часть приложения реализуется с использованием библиотеки `React`. Данный инструмент подходит для построения одностраничного веб-приложения, в котором пользователь может без полной перезагрузки страницы просматривать заявки, работать с профилем, создавать шаблоны и отправлять отклики. Для сборки клиентского приложения используется `Vite`, так как он обеспечивает быструю разработку, удобную структуру проекта и простую подготовку production-сборки. Навигация между страницами реализуется с помощью `React Router`, что позволяет выделить отдельные маршруты для каталога заявок, авторизации, регистрации, профиля, создания заявки и сообщений [7].

Серверная часть разрабатывается на платформе `Node.js` с использованием фреймворка `Express`. Серверное приложение принимает HTTP-запросы, выполняет валидацию входных данных, обрабатывает бизнес-логику, проверяет права доступа и возвращает клиентской части структурированные JSON-ответы. Для проверки данных используется библиотека `express-validator`, что позволяет централизованно задавать ограничения для форм регистрации, авторизации, шаблонов, заявок, откликов и сообщений.

В качестве системы управления базой данных выбрана `PostgreSQL`. Реляционная модель хорошо подходит для разрабатываемого приложения, так как основные сущности имеют устойчивые связи между собой: пользователь создает шаблоны, на основе шаблонов публикуются заявки, к заявкам относятся отклики, а отклики связаны с диалогами и сообщениями. Для взаимодействия серверной части с базой данных используется `Prisma ORM`. Prisma позволяет описывать структуру данных в виде схемы, генерировать клиент для работы с базой данных и уменьшать количество ручного SQL-кода при реализации типовых операций [8], [9].

Для аутентификации пользователей используется механизм `JWT`. После успешной регистрации или входа сервер формирует токен, который клиентская часть сохраняет и передает в последующих запросах. Такой подход позволяет защищать маршруты, доступные только авторизованным пользователям, например создание шаблонов, публикацию заявок, отправку откликов и работу с сообщениями. Разграничение прав реализуется через поле роли пользователя, принимающее значения обычного пользователя или администратора.

При разработке также учитывается методология Twelve-Factor App. В частности, конфигурация приложения выносится во внешние переменные окружения, зависимости фиксируются в `package.json`, а база данных рассматривается как подключаемый внешний сервис. Это важно для последующего запуска приложения в контейнерах и развертывания в облачной среде [4].

Таблица 4 — Программный стек проекта

| Уровень приложения | Используемые технологии | Версия | Назначение |
|---|---|---|---|
| Клиентская часть | React | 19.2.6 | Построение пользовательского интерфейса |
| Клиентская часть | React Router | 7.15.1 | Маршрутизация между страницами приложения |
| Клиентская часть | Vite | 6.4.2 | Сборка и запуск клиентского приложения |
| Серверная часть | Node.js | определяется средой выполнения | Запуск серверного JavaScript-приложения |

| База данных | PostgreSQL | определяется установленным сервером БД | Хранение пользователей, шаблонов, заявок, откликов, диалогов и сообщений |
| ORM | Prisma Client | 6.19.3 | Взаимодействие серверной части с базой данных |
| ORM | Prisma CLI | 6.19.3 | Генерация клиента, проверка схемы и выполнение миграций |
| Аутентификация | jsonwebtoken | 9.0.3 | Создание и проверка JWT-токенов |

Такой набор технологий позволяет реализовать полноценное клиент-серверное приложение, сохранить разделение ответственности между слоями системы и обеспечить основу для дальнейшего тестирования, контейнеризации и развертывания.
