# Платформа для поиска команд в онлайн-игры

Курсовая работа по дисциплине "Проектирование и разработка клиент-серверных приложений".

## Структура проекта

- `/server` - серверная часть на Node.js, Express и Prisma
- `/client` - клиентская часть на React и Vite
- `/docs` - рабочие материалы по отчету и проектированию
- `docker-compose.yml` - локальный запуск базы данных, сервера и клиента
- `docker-compose.prod.yml` - запуск опубликованных Docker-образов

## Стек технологий

- React + Vite
- Node.js + Express
- PostgreSQL
- Prisma ORM
- JWT
- Docker
- GitHub Actions

## Переменные окружения

Для локального запуска необходимо создать файл `.env` в корне проекта по примеру `.env.example`. Файл `.env` не добавляется в Git, так как содержит пароль базы данных, строку подключения и секрет JWT.

Для GitHub Actions необходимо добавить секреты в разделе `Settings -> Secrets and variables -> Actions`:

- `DATABASE_URL` - строка подключения к базе данных для серверных проверок;
- `JWT_SECRET` - секретный ключ для подписи JWT;

Клиентская часть в Docker-режиме обращается к API по относительному пути `/api`. Запросы проксируются Nginx в серверный контейнер, поэтому отдельный секрет `VITE_API_URL` для GitHub Actions не требуется.

## Запуск проекта

### Запуск через Docker Compose

1. Создать файл `.env` в корне проекта по примеру `.env.example`.

2. Запустить контейнеры:

```powershell
docker compose up --build
```

3. Открыть клиентскую часть:

```text
http://localhost:5173
```

4. Проверить серверную часть:

```text
http://localhost:5000/api/health
```

При запуске Docker Compose миграции выполняются отдельным одноразовым сервисом `migrate`, после чего запускается сервер. Тестовые данные автоматически не создаются.

Для разового заполнения локальной базы демонстрационными данными используется команда:

```powershell
docker compose --profile seed run --rm seed
```

### Локальный запуск без Docker

Для локального запуска без Docker потребуется установленный PostgreSQL и заполненная переменная `DATABASE_URL`.

1. Установить зависимости серверной части:

```powershell
cd server
npm install
```

2. Применить миграции базы данных:

```powershell
npm run prisma:deploy
```

При необходимости демонстрационные данные создаются отдельной командой:

```powershell
npm run prisma:seed
```

3. Запустить сервер:

```powershell
npm run dev
```

4. В отдельном терминале установить зависимости и запустить клиентскую часть:

```powershell
cd client
npm install
npm run dev
```

По умолчанию клиентская часть доступна по адресу `http://localhost:5173`, серверная часть - по адресу `http://localhost:5000`.

## Проверка проекта

Серверные тесты:

```powershell
cd server
npm test
```

Набор включает smoke-проверки API, интеграционные сценарии для RBAC, владения профилями, шаблонами и заявками, модерации, откликов и доступа к диалогам, а также прямые проверки ограничений PostgreSQL. Тесты базы данных подтверждают принадлежность шаблона автору заявки, корректность состава диалогов, участие отправителя сообщения и согласованность отклика. Для запуска требуется доступная PostgreSQL, указанная в `DATABASE_URL`, и выполненная команда `npm run prisma:deploy`.

Фаззинг-тестирование серверной части:

```powershell
cd server
npm run fuzz
```

Фаззинг охватывает body-, path-, query- и header-параметры публичных и защищённых маршрутов. Скрипт использует воспроизводимый seed, проверяет отсутствие ответов `5xx`, тайм-аутов и некорректного формата ответа, а после выполнения удаляет созданные данные. Количество итераций и seed задаются переменными `FUZZ_ITERATIONS` и `FUZZ_SEED`.

Клиентские тесты:

```powershell
cd client
npm test
```

Клиентский набор проверяет utility- и API-функции, а также серверное отображение React-компонентов авторизации, административной панели, выхода из профиля и страницы 404.

Сборка клиентской части:

```powershell
cd client
npm run build
```

## CI/CD и Docker-образы

При успешном запуске workflow из веток `master` или `main` Docker-образы публикуются в GitHub Container Registry:

- `ghcr.io/kaprun17/ddcsa-coursework-server:latest`
- `ghcr.io/kaprun17/ddcsa-coursework-client:latest`

Также для каждого образа создается тег с SHA коммита, что позволяет развернуть конкретную версию приложения.

Для запуска опубликованных образов можно использовать отдельный compose-файл:

```powershell
docker compose -f docker-compose.prod.yml up -d
```

## Развертывание

Приложение может быть развернуто на Render по схеме:

- PostgreSQL Database - база данных приложения
- Web Service - серверная часть
- Static Site - клиентская часть

Для серверной части необходимо указать переменные окружения `DATABASE_URL`, `JWT_SECRET`, `NODE_ENV` и `PORT`. Для клиентской части на Render необходимо указать переменную `VITE_API_URL` со значением вида:

```text
https://<server-service-name>.onrender.com/api
```

Для Web Service в поле Pre-Deploy Command указывается `npm run prisma:deploy`. Основная команда запуска остается `npm start`, поэтому миграции выполняются отдельно от рабочего процесса API.

Для корректной работы клиентской маршрутизации в Static Site необходимо добавить правило rewrite:

```text
/* -> /index.html
```

Инструкция для размещения приложения на виртуальной машине Cloud Ru находится в `deploy/cloudru/README.md`.

## Тестовые данные

После настройки переменной `DATABASE_URL` и применения схемы Prisma можно заполнить базу тестовыми данными:

```powershell
cd server
npm run prisma:seed
```

Скрипт создает администратора, двух обычных пользователей, игровые шаблоны, заявки, отклик и тестовый диалог. Повторный запуск не очищает базу данных и не должен создавать дубликаты основных записей.

Тестовые учетные записи:

- `admin@teamfinder.test` / `Test12345!`
- `player@teamfinder.test` / `Test12345!`
- `captain@teamfinder.test` / `Test12345!`
